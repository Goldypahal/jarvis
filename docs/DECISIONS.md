# Decisions

Each entry: date · decision · why · how to reverse. The agent adds to this file; it does not
reopen an entry without a new reason.

- **2026-11-17 · Oblivion is the only engine; NEXUS moves to `legacy/`.** NEXUS returns canned
  text and has security holes S1–S3; keeping two engines doubles all work. Reverse: `git mv`
  `legacy/nexus` back and restore the adapter import in `web/app.py`.
- **2026-11-17 · The desktop moves from Flask into Oblivion (axum) in month 3.** Needed for a
  one-file install without Python. Flask stays until then. Reverse: keep `web/` and the bridge.
- **2026-11-17 · Names: "Jarvis" is the desktop, "Oblivion" is the engine.**
- **2026-11-17 · Privacy default.** File contents may go to cloud models only when a cloud key
  is configured; the "Offline" switch forces local models only.
- **2026-11-17 · Autopilot.** The coding agent works through `PROGRESS.md` without asking,
  within the limits in `.agents/rules/autopilot.md`. Merges to `main` only at milestones.
- **2026-11-19 · Desktop template and static assets embedded directly in Axum binary with rust-embed.** Eliminates runtime Python or Flask requirement for the executive desktop interface. Zero external file dependencies for web serving; secret token injected into embedded HTML at runtime; classic chat remains accessible via `/classic`. Reverse: remove `rust-embed` and revert `page` handler in `crates/oblivion-cli/src/web.rs`.
- **2026-11-20 · First-run onboarding wizard and autostart integration with WiX installer.** First-run wizard manages workspace selection, model privacy mode (local vs hybrid), and Windows autostart (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`), accessible via CLI (`--wizard`, `--autostart`), REST endpoints, and desktop UI modal. Packaging pipeline in `installer/build_installer.ps1` builds release executable, packages portable zip, and generates WiX MSI specification; code signing marked BLOCKED (needs user) for certificate provision. Reverse: remove `autostart.rs`, `wizard.rs`, and `installer/` directory.
- **2026-11-20 · Voice subsystem with push-to-talk, audio buffer WAV parsing, and local/cloud STT.** Push-to-talk hotkey (`Ctrl+Space`) and mic buttons in menubar (`#menubar-mic-btn`) and Oblivion panel (`#ob-mic-btn`) with pulsing recording visual states. Audio capture via Web Speech API or `getUserMedia` -> `/api/oblivion/voice/transcribe`. Backend `VoiceService` routes between `LocalWhisperTranscriber` (via `whisper-cli`/`whisper.exe`), `CloudWhisperTranscriber` (Groq/OpenAI Whisper when configured and not offline), and pure-Rust 16kHz mono WAV audio parsing. Reverse: remove `voice.rs` and voice REST endpoints.
- **2026-11-20 · Sentence-by-sentence TTS streaming with code suppression and instant barge-in.** Token-by-token sentence boundary detection (`. `, `! `, `? `, `\n\n`) in `SentenceSplitter` omits markdown code fences so syntax is not read aloud into audio. Frontend queues and streams sentence-by-sentence via native `window.speechSynthesis` with backend fallback to local Piper TTS (`/api/oblivion/voice/tts/speak`). Barge-in halts speech playback immediately on PTT trigger, text send, or Escape key. Menubar speaker button (`#menubar-speaker-btn`) provides one-click mute/unmute. Reverse: remove `SentenceSplitter` and `voice.js` speech synthesis queue.
- **2026-11-20 · Spoken-reply style and voice approvals restricted to low-risk actions.** Requests initiated via voice or `/spoken on` inject concise conversational guidelines into the system prompt (short answers, code omitted from audio, full details directed to panel). Voice approval ("yes" / "no") is strictly gated via `is_low_risk_action`: low-risk actions (read-only outside workspace, memory storage, web fetches) permit spoken affirmative approval, while high-risk actions (file edits, file writes, shell execution, destructive keywords) strictly reject voice affirmative approvals with 403 Forbidden and audio alerts, requiring explicit manual click confirmation. Reverse: remove `is_low_risk_action` and voice gating in `Approvals::answer_with_source`.
- **2026-11-20 · Image input in provider layer and multi-modal attachments across all interfaces.** Added `ImageAttachment` in `oblivion-providers` supporting data URIs and multi-part serialization for OpenAI/Groq/OpenRouter multimodal wire format and Ollama images array. Multimodal turns supported via `run_turn_with_images` in `oblivion-core` with automatic `RequestClass::Vision` classification. Interactive image attachment support implemented across CLI (`--image <path>`, `/image <path> [prompt]`), TUI (`[images: ...]`), Axum REST/SSE (`/api/chat` and `/send`), Python desktop bridge (`send_and_wait(..., images=...)`), and desktop web UI (attach button, drag-and-drop, clipboard paste, staging preview tray with remove chips, user message thumbnails). Reverse: remove `ImageAttachment` and revert image parameters across providers, core, CLI, bridge, and UI.
- **2026-11-20 · "Look at my screen" screenshot capture with preview before sending.** Added `screen.rs` in `oblivion-cli` capturing desktop display into base64 PNG `ImageAttachment` (via PowerShell GDI CopyFromScreen on Windows with fallback in non-interactive/test environments). Supported in CLI (`--screen`, `/screen [prompt]`), Axum REST/SSE (`/api/oblivion/screen/capture`), Python bridge, and desktop web UI (`#ob-screen-btn` 🖥️ in composer, `lookAtScreen()` using `getDisplayMedia` with backend fallback). Privacy guarantee: screenshots are staged into `#ob-image-preview-tray` with thumbnail and remove button for user inspection before sending, never sent silently. Reverse: remove `screen.rs`, `--screen` flag, and screen routes.
- **2026-11-20 · Browser agent screenshot fallback for picture-only pages.** Added `is_insufficient_page_text` in `oblivion-mcp::browser` detecting picture-only, diagram, canvas, or graphic web pages where DOM outlines lack sufficient substantive text (< 120 chars when visual elements are present or < 40 chars total). Implemented `capture_screenshot` and `action: "screenshot"` in `BrowserTool`, automatically capturing and attaching a PNG screenshot fallback during `open` and `snapshot`. Extended `ToolOutput` with multimodal `ImageAttachment` parsing (`extract_attached_images`), attaching images to `Message::tool_result` in `Agent` turn execution and dynamically routing to `RequestClass::Vision`. Added visual practice quiz test page `oblivion/evals/sites/picture_quiz.html`. Reverse: remove screenshot fallback from `browser.rs` and revert `ToolOutput` to text-only.
